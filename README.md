# xHOSM — редизайн интерфейса

Рабочие материалы: переделываем интерфейс xHOSM в удобный и понятный, на дизайн-системе iiko.
Аудитория — поддержка L3 (основная), L3 Web, аналитики, инфраструктура, партнёры.

**Прототип:** `2/index.html` — новый интерфейс по «Заданию на отрисовку v1»: 12 экранов, сборка строго по ДС (компоненты `ds-*`, токены; свои классы — только обвязка `xh-*`).
ДС подключена относительно: `../../DS/iiko-ds-web/` — копия ДС лежит в этом же репозитории (`DS/iiko-ds-web/`), поэтому прототип открывается автономно (в т.ч. через GitHub Pages).
Локальный просмотр: статический сервер на корне `C:\Users\asukharev\GitHub\` (порт 8123) → `/XHosm/2/index.html`.
Навигация — хэш-роуты: `#/desk #/search #/tasks #/clients #/servers #/client #/server #/logs #/data #/lic #/bulk #/wiz`; состояния — `?state=loading|empty|error|zip|noaccess|stopped|external`; деградация — `?degraded=1`; режим партнёра — `?role=partner`.

## Прототип

- `2/index.html` — **актуальный прототип** нового интерфейса по «Заданию на отрисовку v1»: строго на ДС, интерактивный (все сценарии проверяются живыми кликами); материалы, сценарии и отчёты — в `2/`.
- `index.html` (в корне) — старый черновик (структура «Клиент и сервер»), не развивается.
- `DS/iiko-ds-web/` — копия дизайн-системы для автономного просмотра (источник — репозиторий `iiko-DS/iiko-ds`; обновляется копированием).
- `xHOSM_структура_прототипа_выводы_v1.md` — почему структура именно такая: выводы из болей, сценариев и гипотез.

## Сборка документов

- `build_*.py` — скрипты генерации PDF (reportlab, шрифты DejaVu). Запуск: `uv run --no-project --with reportlab python <скрипт>.py`
