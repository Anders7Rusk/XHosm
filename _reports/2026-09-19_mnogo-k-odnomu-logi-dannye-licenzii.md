# «Много → один»: Логи · Данные · Лицензии

**Дата:** 2026-09-19. **Сигнал:** «делай» (по предложению из `2026-09-19_katalogi-klienty-servera.md`).

**Принцип:** раздел меню сначала показывает всю совокупность (область/каталог и фильтры), действия — над выборкой (вплоть до массовых), и только затем drill-in в один объект. Раньше так были собраны Стол/Поиск/ЦЗ/Клиенты/Серверы/Массовые — теперь и эти три раздела.

## Паспорта (сценарий → гипотеза → состав → проверка)

### 1. Логи — SC-08 «Логи: посмотреть, найти, скачать» («постоянно при разборе»), UI-L3-06

- **Было:** экран «одного сервера» (klient-142) — «поиск по всем файлам» = файлы одного сервера.
- **Стало:** строка «Область поиска» — чипсы: Этот сервер · Все серверы клиента (2) · Кластер RU-2 (137) · Список серверов. Под строкой поиска — карточка-сводка «Найдено: ERROR · 17–18.09 — 21 вхождение · 3 файла · 2 сервера» с разбивкой по серверам (klient-142 — «открыт ниже»; klient-141 — ссылка). Категории/файл/лог-строки остаются уровнем ниже — drill-in одного сервера (у «Категорий» подпись «klient-142.iiko.it — открыт из сводки»).
- **Проверка:** чипсы переключаются (клик по «Кластер RU-2» зажигает его); сводка на месте; кнопка «Найти по всем» отвечает снекбаром про сводку.

### 2. Данные — SC-13 «SQL-запросы по базе клиента» (ежедневно), SC-09 «Бэкап БД» (часто), SC-10 «Восстановление / перенос / копирование» (часто), UI-L3-07/08/10

- **Было:** шапка «сервер klient-142.iiko.it» — объект как будто уже один, хотя операции задуманы массовыми (SQL до 1500 серверов, бэкап/перенос до 5).
- **Стало:** строка «Объекты операции» над табами — чипсы: Этот сервер · Клиент: Кулинарная лавка (2 сервера) · Кластер RU-2 (137) · Список из поиска; лимиты видны в подписи. Результат запроса — с колонкой «Сервер» (klient-141/142, ссылки на карточки). «История бэкапов» — «все серверы области» + колонка «Сервер». Файлы восстановления подписаны сервером. Баннер «уже идёт бэкап» переведён с burger-house на klient-141 — конфликт внутри области.
- **Проверка:** чипсы; заголовки результата `Сервер · uuid смены · Открыта · Сумма`; истории `Сервер · Дата · Тип · Размер · Хранение`; ссылки серверов ведут в карточку.

### 3. Лицензии и Cloud — SC-04 «Лицензии: „не работает лицензия / API / Cloud"» (ежедневно), UI-L3-02, BR-LIC-001…005

- **Было:** воркбенч на один UID — как будто лицензия уже найдена.
- **Стало:** каталог «Лицензии клиентов» (6 из 141; UID · клиент · сервер · состояние: красный Cloud / ревизия ждёт / ок / демо) над воркбенчем; фильтр-чипсы; выбор строк → панель «Выбрано: N» и кнопка «Прогнать маршрут по выбранным» (принцип как в «Массовых»: предпросмотр/построчный отчёт). Клик по UID подставляет его в «Операции с лицензией» и прокручивает к карточке; клиент и сервер — ссылки в карточки.
- **Проверка:** 6 строк; выбор 1 → «Выбрано: 1»; «выбрать все» → 6; снятие → панель скрыта; клик по UID 812-334-557 → поле `#lic-uid` = 812-334-557 + снекбар; ссылка сервера → `#/server`.

## Найдено и починено по пути

- `updateSel` задевал панели массовых действий **всех** таблиц документа — теперь скоупится по `[data-check-scope]`: панель и счётчики обновляются только у своей таблицы (проверено: выбор в каталоге лицензий не зажигает панель на «Поиске»).

## Открытые вопросы

- Фильтр-чипсы «Все / Проблемные (2) / Демо» в каталоге лицензий — визуальные (как в остальных каталогах прототипа); реальная фильтрация строк — при желании.
- Клик по серверу в сводке Логов — пока симуляция; можно сделать переключение drill-in на выбранный сервер.
- «Список из поиска» — в проде подтягивает выделенные строки из результатов Поиска (механика выбора там уже есть).
- Мастера не трогали: тяжёлая операция ведёт один объект шагами — так и задумано.
