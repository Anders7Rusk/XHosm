## 2. Общие сведения о проекте (§1)

- **Название:** xHOSM (eXtended Hosting Operations & Systems Management)
- **Краткое описание:** Централизованная система управления облачным хостингом iikoRMS/Syrve серверов в Kubernetes-кластерах с поддержкой нескольких регионов (RU, EU, KZ, UZ)
- **Основание:** Внутренний DevOps-инструмент iiko
- **Приоритет:** Red Критический — core-инфраструктура хостинга

### 2.1. Что делает система (§3.1)

1. **Управление жизненным циклом серверов:** создание новых cloud-серверов (доменов) · обновление версий iikoRMS · миграция между кластерами/регионами · архивирование неактивных серверов
2. **Операции с базами данных:** резервное копирование (backup) · восстановление из бэкапа (restore) · конвертация между MSSQL ↔ PostgreSQL · управление периодом хранения данных (dbperiod)
3. **Мониторинг и диагностика:** проверка статусов серверов · мониторинг памяти и ресурсов · анализ логов ошибок · проверка подключений к Chain/iikoBiz
4. **Интеграция с Service Desk:** автоматическая обработка тикетов Pyrus · создание задач на обновление/бэкап · уведомления о статусах операций
5. **Планирование задач:** Scheduler для отложенных операций · автоматические рестарты в техническое окно · ежедневные/еженедельные регулярные задачи

**Бизнес-ценность:** централизованное управление 10000+ облачных серверов клиентов · автоматизация рутинных операций DevOps · снижение времени реакции на инциденты · масштабирование на несколько географических регионов.

### 6.2. User Stories — 30 сценариев из эксплуатации (§11.1)

> Формат документа: «Как [роль] · Я хочу [действие] · Чтобы [цель]», плюс частота, контекст и критерии приёмки (AC).

#### Управление службами (критически важно)

**US-001. Очистка unsaved_data для восстановления обмена**
- Как: специалист L3 Support · Хочу: удалить unsaved_data.xml и перезапустить сервер · Чтобы: восстановить обмен RMS↔Chain/RMS↔Front при «застрявших» сущностях
- Частота: очень часто (ежедневно). Контекст: дублирующиеся заказы в очереди обмена; «застрявшие» сущности не синхронизируются; проблемы обмена после удаления сущности на фронте
- AC-001.1: могу выбрать checkbox «Удалить unsaved_data» в модуле «Служба» · AC-001.2: перезапуск выполняется с очисткой файла · AC-001.3: очередь обмена возобновляет движение после рестарта · AC-001.4: вижу статус операции в истории сервера
- Workflow: 1) на фронте удаляется «застрявший» заказ/сущность → 2) в xHOSM выбирается галка «Удалить unsaved_data» → 3) сервер перезапускается → 4) очередь обмена возобновляет движение

**US-002. Перезапуск с очисткой кэша лицензий**
- Как: L3 Support · Хочу: перезапустить сервер с удалением HostAccess.dat и LicensingState.dat · Чтобы: устранить конфликт старых и новых лицензий
- Частота: часто
- AC-002.1: могу выбрать checkbox «Удалить HostAccess» (удаляет HostAccess.dat + RestrictionState.dat) · AC-002.2: могу выбрать checkbox «Удалить LicState» (удаляет LicensingState.dat) · AC-002.3: перезапуск выполняется с удалением выбранных файлов · AC-002.4: после рестарта сервер корректно получает актуальные лицензии

#### Диагностика проблем (критически важно)

**US-003. Создание демо-стенда для воспроизведения проблемы**
- Как: L3 Support · Хочу: развернуть копию клиентского сервера на демо-стенде · Чтобы: воспроизвести и диагностировать проблему без риска для продакшена
- Частота: очень часто. Контекст: L3 не может экспериментировать на продакшен-сервере клиента; нужна точная копия данных для воспроизведения бага; демо-лицензия не позволяет развернуть базу с > 150,000 продаж
- AC-003.1: могу создать демо-сервер на нужной версии · AC-003.2: могу восстановить бэкап клиента на демо-сервер · AC-003.3: для баз с продажами > 150,000 требуется боевая лицензия (запрос через партнёрских менеджеров) · AC-003.4: могу удалить демо-сервер после решения проблемы
- Workflow: 1) создать демо-сервер на нужной версии → 2) запросить боевую лицензию у партнёрских менеджеров (если продаж > 150k) → 3) восстановить бэкап клиента → 4) воспроизвести и диагностировать → 5) удалить демо-сервер

**US-004. Выполнение SQL-запросов для поиска данных**
- Как: L3 Support · Хочу: выполнить SQL-запрос к БД клиента · Чтобы: найти проблемные данные или проверить состояние БД
- Частота: очень часто
- AC-004.1: могу выполнить произвольный SQL SELECT запрос · AC-004.2: могу выполнить «тяжёлый» запрос с перезапуском сервера · AC-004.3: результат отображается в UI или доступен для скачивания · AC-004.4: есть кнопки-макросы для частых запросов по статьям БЗ

**US-005. Выполнение Groovy-скриптов без перезапуска**
- Как: L3 Support · Хочу: выполнить Groovy-скрипт на сервере без перезапуска · Чтобы: применить изменения мгновенно (особенно критично для больших серверов)
- Частота: очень часто. Контекст: огромный сервер может перезапускаться 2.5 часа; Groovy позволяет применить изменения «на лету»; используется для отвязки RMS от Chain (KB 334)
- AC-005.1: могу выполнить Groovy-скрипт без остановки сервера · AC-005.2: изменения применяются мгновенно · AC-005.3: есть готовые макросы по статьям Базы Знаний · AC-005.4: вижу результат выполнения скрипта

#### Управление лицензиями (активно)

**US-006. Устранение «зависших» лицензий**
- Как: L3 Support · Хочу: обновить кэш лицензий или поднять ревизию · Чтобы: устранить проблему зависшей лицензии (при переходе с обещанного платежа на обычный счёт)
- Частота: часто. Важно: L3 не добавляет лицензии — только «лечит» зависшие. Добавление — зона ответственности партнёрского отдела.
- AC-006.1: могу обновить кэш лицензий в CRM · AC-006.2: могу поднять ревизию лицензии, если она не активировалась · AC-006.3: могу сбросить привязки старых лицензий · AC-006.4: могу перейти в CRM по кнопке goCRM

#### Управление конфигурацией (активно)

**US-007. Открытие периода редактирования документов**
- Как: L3 Support · Хочу: изменить период редактирования документов (db-period-length-days) · Чтобы: клиент мог редактировать документы «задним числом»
- Частота: очень часто. Контекст: стандарт — 65 дней; запросы клиентов — до 365 дней; формула — от сегодняшней даты минус N дней; планируется самообслуживание клиентов (7 дней раз в месяц)
- AC-007.1: могу изменить параметр db-period-length-days через модуль «Конфигурация» · AC-007.2: изменение применяется после перезапуска сервера · AC-007.3: вижу текущее значение периода в карточке домена

**US-008. Увеличение памяти для больших отчётов**
- Как: L3 Support · Хочу: увеличить RAM (Xmx) сервера · Чтобы: сервер не падал при построении больших отчётов
- Частота: очень часто. Контекст: встроенный калькулятор памяти часто работает некорректно; приходится выставлять RAM вручную; факторы — кол-во фронтов, кол-во RMS в сети, нагрузка при пересчёте таблиц
- AC-008.1: могу изменить значение memory (Xmx) в модуле «Конфигурация» · AC-008.2: могу включить/отключить динамический расчёт памяти · AC-008.3: после изменения требуется пересоздание службы · AC-008.4: калькулятор RAM работает корректно (известная проблема)

**US-009. Установка связи RMS↔Chain (репликация)**
- Как: L3 Support · Хочу: включить параметр enable_replication в resto.properties · Чтобы: подключить RMS к сети ресторанов (Chain)
- Частота: периодически
- AC-009.1: могу изменить параметр enable-replication · AC-009.2: могу указать franchise-server-url (URL Chain-сервера) · AC-009.3: изменение применяется после перезапуска

#### Бэкапы и миграция (критически важно)

**US-013. Восстановление из бэкапа**

### 7.9. Поиск (§3.7, §15.7)

- **Что можно искать:** номер клиента (CRM ID) · UID лицензии (NNN-NNN-NNN) · адрес сервера или его часть (iiko.it и syrve.online) · имя кластера · имя SQL-сервера · произвольный WHERE-запрос · несколько значений сразу (до 1000 CRM ID за запрос, можно построчно).
- **Продвинутый режим (WHERE):** спецвыражения — resto_properties (поиск по настройкам) · java_options (по JVM-параметрам) · idle_middle (середина «тихого окна») · node='node@cluster' (серверы на физической ноде). Из WHERE-запросов автоматически вырезаются INSERT, UPDATE, DELETE, TRUNCATE, DROP, ALTER — поиск только для чтения.
- **Фильтрация по правам:** по брендам · по дилерам (партнёрская поддержка видит только своих) · по клиентам · демо-серверы (модуль DSM) · Exclusive Mode (закреплённый сервер — доступ только с правом HAL). Два разных сотрудника по одинаковому запросу видят разные результаты.
- **«Связанные» серверы (Shift + «Найти»):** нашли Chain → подгружаются все дочерние RMS; нашли RMS → его Chain и все точки сети.
- **Поиск клиентов вне облака:** если серверов не найдено, система обращается к CRM — показывает клиента, лицензии, наличие iikoWeb с пометкой «внешний».
- **Элементы (§15.7):** поле поиска (множественный поиск по строкам) · «Найти» (Ctrl+Enter) · «Кол-во» (найдено строк) · «Показать все» · «Экспорт CSV».

**Статусы сервиса (мониторинг, §3.10.3):** RUNNING (работает) · STOPPED (остановлен, K8s: replicas = 0) · N/F (не найден) · ERR (ошибка подключения) · BAD (аварийный) · N/A (нет данных о кластере/сервисе) · DND (режим «не беспокоить»).

**Цветовая схема статусов (§15.9):**

| Статус | Background | Значение |
|---|---|---|
| Auto | lightgreen | Работает нормально |
| Stopped/Manual | lightyellow | Остановлен вручную |
| Demo | lightcyan | Демо-сервер |
| Error | lightpink / red | Ошибка |
| Upgrading | lightorange | Обновляется |
| Archived | lightgray | В архиве |
| Creating | white (blink) | Создаётся |

Дополнительные индикаторы (§3.10.4): красная строка — критично мало свободной памяти (max ≈ total, free < 100 МБ) · жёлтая строка — расширенные метрики получены, всё в норме · красный терминал — терминал с версией «undefined» (потерял связь).

**Горячие клавиши (§15.10):** Ctrl+Enter — поиск (в textarea) · Ctrl+Enter — отвязать UID (в модуле Лицензии) · Shift+Click — расширенный поиск.

### 7.11. Сервисные факты, важные для интерфейса

- **Автообновление статусов (§3.10):** периоды Off / 20 (по умолчанию) / 60 / 300 / 900 сек · при загрузке страницы возобновляется, если было включено · при отметке сервера более 900 сек галка снимается автоматически · таймаут опроса — 5 секунд на сервер.
- **Логи (§3.11):** окно с двумя панелями (категории | содержимое). Категории: Server (error.log, full.log, startup.log, threaddump.log) · Catalina · Archive (текущий) · Archive (старый) · Front · Franchise. Быстрые ссылки: error.log, full.log, JMS.log, startup.log, threaddump.log. Кнопка «ZIP» (с опцией ротационных zip-логов, только K8s) · кнопка «Egais». Создание архива — до 5 минут.
- **BackOffice (§3.11.4):** иконка в строке результата (🏢 BackOffice / 🔗 ChainOffice) — скачивается .xhosm-файл для автоподключения к серверу (ровно та версия BackOffice, что на сервере; кэшируется; для архивных скрыта).
- **Прогрессы/уведомления (§3.9.8):** обновления сборок и операций в реальном времени через WebSocket (Centrifugo): текущий этап, процент выполнения, успех/ошибка.

## 13. Нефункциональные требования (§12)

**Производительность:** время создания домена < 5 мин (текущее 3–5 мин) · время обновления версии < 10 мин (5–15) · backup PostgreSQL < 30 мин до 50 ГБ · время ответа API (поиск) < 2 сек (0.5–2) · scheduler throughput > 500 задач/час (~500–1500).

**Доступность:** uptime xHOSM 99.9% · плановое обслуживание вне рабочих часов (ночь) · RTO < 1 час · RPO < 24 часа.

**Безопасность:** аутентификация LDAP (Active Directory) + JWT · авторизация RBAC по модулям · шифрование HTTPS (TLS 1.2+) · аудит действий — таблица user_actions_history.

## 16. Приложения документа (для справки)

- **Чек-лист создания домена:** CRM ID существует и активен → имя домена валидно и уникально → выбран правильный регион по стране → кластер имеет достаточно ресурсов → версия ≥ минимальной → при репликации Chain доступен → уведомление отправлено.
- **Чек-лист обновления версии:** текущий статус = Auto → дистрибутив существует → достаточно места на диске → backup создан (для больших БД) → уведомление клиенту отправлено → выполнено в техническое окно.
- **Чек-лист backup/restore:** достаточно места на backup-сервере → сервер остановлен (для consistent backup) → файл успешно создан → контрольная сумма проверена → при restore версия совместима → при restore БД пересоздана.
- **В приложении к документу также есть:** 4 JSON-примера данных (типичный RMS-сервер, Chain-сервер, демо-сервер EU, задача scheduler) и Mermaid-схемы (workflow создания сервера, state machine статусов).
- **Не включено в этот сбор (есть на вики):** API-контракты CGI (createdomain/tomcatman/dbtools/configman/search), формат ответа API, экспорты и выгрузки, структуры таблиц БД и ER-диаграмма, cron-задачи, batch-скрипты, миграции и апгрейды, JS-модули, региональная архитектура.
