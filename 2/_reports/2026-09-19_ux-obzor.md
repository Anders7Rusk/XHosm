# Отчёт: UX-обзор прототипа — 19.09.2026

**Контекст:** сформирован после полного прогона (36 UI-сценариев + 34 сценария работы). Отвечает на вопрос «что менять в интерфейсе» — отдельно от «сценарий проходит / не проходит».

**Важно:** прогон подтверждает покрытие и работу механик, но НЕ доказывает удобство и оптимальность путей — это проверяется пилотом с людьми и метриками (см. раздел D).

## A. Быстрые правки (механика, дни работы)

1. **Чипсы — ✅ ЗАКРЫТО 19.09:** крестик снимает чипс-фильтр; клик по чипсу без крестика выбирает один в группе (шаблоны «Массовых», уровни логов, макросы из БЗ).
2. **«Выбрать всё» — ✅ ЗАКРЫТО 19.09:** промежуточное состояние (`indeterminate` из ДС) при частичном выборе.
3. Действия строк по ховеру — показывать ли главное действие всегда (для новичков и тач-режима) — **ЖДЁТ РЕШЕНИЯ**.
4. «История операций» по клику на пользователя — формат: снекбар / дропдаун «Мои операции» / панель — **ЖДЁТ РЕШЕНИЯ**.
5. BR-коды (`BR-SVC-001` и т.п.) — прятать ли под «подробнее» для партнёров/новичков — **ЖДЁТ РЕШЕНИЯ**.
6. Селекты и таймпикеры не раскрываются (витрина) — решить, нужен ли интерактив в прототипе.

## B. Экранные улучшения (кандидаты, по одному можно брать выборочно)

1. Стол: «взять в работу» из «Требует внимания» (след в Центре задач) + сортировка по критичности.
2. Поиск: «недавние запросы», подсветка совпадений, быстрый peek сервера из строки.
3. Карточка сервера: «липкая» статус-карточка при прокрутке вкладок; кнопка «задачи этого сервера».
4. Центр задач: группировка по клиенту/риску/времени; поиск по задачам; (фильтры-чипсы уже оживлены).
5. Логи: «к следующей ошибке»; диапазон дат — в URL для шаринга (ссылка уже копируется).
6. Массовые: сохранённые фильтры выборки (шаблоны уже переключаются).
7. Диалоги-планы: по клику на шаг показывать «что делает шаг» (сейчас — подсветка).
8. Лицензии: при неуспехе маршрута — кнопка «следующий шаг» (Bcrypt / reset) вместо текста.
9. Мастера: shrink — эталонный паттерн (проверки → авто-бэкап → этапы → отмена → пометка), тиражировать на RMS→Chain и франшизу; NSR — отложен решением 19.09.
10. Навигация: крошки с объектом («Клиент → Сервер»), «назад к результатам поиска» после карточки.

## C. Структурные (решать с командой)

1. **4 слабых места:** группировки в Центре задач; центр уведомлений с подписками (колокольчик сейчас «пусто»); сквозной «мониторинг → действие» со Стола; счётчики Badge.
2. **Роли:** матрица партнёрского самообслуживания (открытый вопрос файла: какие 3–5 действий) + EN-локализация (DO-1218).
3. **«Сказать клиенту»:** шаблон ответа / уведомление после операции (сейчас результат живёт в задачах).
4. **Терминология для новичков:** D/W/M/Q/Y, Тех.окно, DCT/ARC/ABK — расшифровки.
5. **Стартовая навигация:** проверить «Рабочий стол» на новых людях (DO-899).

## D. Метод проверки (пилот, без него списки останутся гипотезами)

1. **3–4 человека разных ролей** (L3, партнёр, аналитик) проходят свои пути из файла сценариев; замер: число шагов, время до результата, ошибки.
2. **Чек-лист по разделу 8 файла** («Вход / Поиск / Статус / Операции / Массовость / Один экран клиента / Права / Новичкам») — сверить каждое обещание вживую.
3. После пилота — приоритизация A → B → C и фиксация результатов отдельным отчётом в этой папке.
