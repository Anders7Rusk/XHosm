# Каталоги «Клиенты» и «Серверы» · фикс роутера · аудит «много vs один»

**Дата:** 2026-09-19.

**По команде заказчика:** «Верни серверы тоже… Поиск это сквозной элемент, доступный с любой страницы, и может искать всё что угодно. Думай»; «Из сценариев нужно уловить саму суть, а не то, как в старом интерфейсе кликали».

## Что делали

1. Пункты рельса «Клиент»/«Сервер» переосмыслены как разделы-каталоги: **«Клиенты»** (`#/clients`) и **«Серверы»** (`#/servers`) — секция «Объекты» между «Работой» и «Инструментами». Поиск остаётся сквозным омнибоксом.
2. Построен экран **Э-11 «Клиенты»** (`v-clients`): шапка «все клиенты контура · 96 всего», кнопки [Обновить из CRM, Экспорт], фильтры (поиск, чипсы Все / Мои (3) / Есть ошибки (1), селекты Тариф/Кластер), таблица 5 строк (клиент · CRM ID · тип · кластер · ответственный · серверы · состояние); из футера — «Поиск по значению».
3. Построен экран **Э-12 «Серверы»** (`v-servers`): шапка «все серверы контура · 137 · клик по домену — карточка», кнопки [Обновить статусы, Массовые действия], фильтры (поиск домен/клиент, чипсы Все / Проблемные (2) / Демо, селекты Кластер/Статус), таблица 6 строк (домен · клиент · роль · статус · кластер · память · версия); домен → карточка сервера, клиент → карточка клиента.

## Как проверяли (живые факты)

- Баланс тегов после вставок: `div 1466/1466 · span 1658/1658 · a 71/71 · button 166/166 · style=0 · section 15/15`.
- Структура DOM: в `v-servers` — 6 строк, в `v-clients` — 5 строк.
- Прогон кликов по всем 10 пунктам рельса — каждый открывает свою секцию и крошки: `desk→v-desk … clients→v-clients · servers→v-servers … wiz→v-wiz`. 0 ошибок JS.
- Drill-in: домен из «Серверов» → `#/server` (карточка), клиент из «Клиентов» → `#/client`.

## Найдено и починено

- **Баг роутера:** маршруты `clients`/`servers` не были добавлены в белый список `VIEWS` — клики по «Клиенты»/«Серверы» в рельсе падали на «Рабочий стол». Исправлено.
- **Урок:** при добавлении секции `v-<id>` обязательно дописывать `id` в `VIEWS` роутера, иначе fallback на desk.

## Аудит «много vs один» (вопрос заказчика)

Заказчик: «страницы собраны как будто мы в поиске нашли 1 клиента или сервер; но у нас много всех и всего»; вопросы: «Данные — тоже по одному? Лицензии? Массовые?»

| Раздел | Сейчас | Вердикт |
|---|---|---|
| Стол · Поиск · ЦЗ · Клиенты · Серверы · Массовые | «много» | ок (Поиск — сквозной; Массовые — эталон: 137 из поиска, волны, построчный отчёт) |
| Карточки Клиент/Сервер | «один» | ок — это drill-in из каталога/поиска |
| **Логи** | один сервер (`klient-142`): «поиск по всем файлам» = файлы одного сервера | перестроить: область поиска (сервер/клиент/кластер/список) + сводка по серверам |
| **Данные** | шапка «сервер klient-142.iiko.it», хотя операции массовые (SQL до 1500 серверов, бэкап до 5) | перестроить: блок «Объекты операции» |
| **Лицензии** | воркбенч на один UID, каталога всех лицензий нет | перестроить: каталог (облачко/ревизии) над воркбенчем |

Причина: экраны писались от кликов старого UI (там они жили внутри карточки сервера / по одному UID) — взяли букву, а не суть.

## Открытый вопрос (ждёт решения)

Перестроить Логи/Данные/Лицензии по модели **«много → один»** (каталог/область → фильтр → выбор → действие, вкл. массовое → drill-in)? Предложение отправлено заказчику; до «го» правок не делаем.
