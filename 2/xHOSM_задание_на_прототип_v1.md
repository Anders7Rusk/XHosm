# xHOSM — задание на отрисовку прототипа (v1)

**Что это:** задание на сборку кликабельного прототипа нового интерфейса xHOSM.
**Основание:** «Ядро для прототипа» (10 тем + каркас) · «Сценарии интерфейса (v2)» (36 путей UI-xx) · «Материалы (v2)»: §7 — функционал старого интерфейса, §8 — что заброшено и не переносится, §9–11 — бизнес-правила, лимиты, тексты.
**Принцип переноса:** старый интерфейс — источник **функционала**, а не отрисовки. Все рабочие функции переносятся в новые экраны в удобном виде; внешний вид — только из дизайн-системы iiko.
**Правила ДС (обязательные):** компоненты — только из библиотеки ДС (`ds-*`); нет компонента или значения в ДС → **стоп и вопрос**; данные 1:1 из источника (`iiko-ds-spec.md`); сборка и проверки — по `/opt/data/iiko-ds-web/RULES.md`.
**Формат результата:** кликабельный HTML-прототип на ДС. Структура «Рабочий стол → Клиент → Сервер». 10 экранов, состояния (обычное / пусто / загрузка / ошибка / деградация), рабочие переходы. Десктоп, ширина макета 1920.

## 1. Общий каркас (на всех экранах)

| Элемент каркаса | Что рисуем | Компоненты ДС |
|---|---|---|
| Вход | SSO-вход, долгая сессия, возврат к контексту | Sidenav_DS, Menu_DS |
| Права и режимы | режимы по правам (в системе 46 кодов: SRV, CFG, IMP, UPD, DGV, BTV, SQR/SQW, GRV, LIC, ARC, DBT, RDO…); недоступное — скрыто или заблокировано с объяснением «почему» | Badge_DS, Hint-Tooltip_DS, Banner_DS |
| Статус с доказательством | источник, свежесть, история, кнопка «перепроверить» — везде, где показан статус | Status_DS, Badge_DS, Hint-Tooltip_DS |
| Операции — процессы | план → шаги → прогресс → результат → уведомление; у всех операций одинаково | Stepper_DS, Dialog_DS, Snackbar_DS |
| Правила inline | у каждого ограничения — «почему нельзя» и «что сделать» | Banner_DS, Hint-Tooltip_DS |
| Уведомления и автодействия | лента «система сделала X», подписки, центр уведомлений | Card_DS, List_DS, Snackbar_DS |
| Деградация | «система замедлена», действие продолжается в фоне, безопасный повтор | Banner_DS, Status_DS |
| Язык | русский; EN и другие языки — не в этой итерации | — |

**Статусы — перевод на палитру ДС.** В старом интерфейсе статусы красились «нативно» (lightgreen/lightyellow/lightpink…). В новом — только тональности ДС (`Status_DS`, токены): успех · в процессе · ошибка · нейтральный · архив/приглушённый · инфо (демо). Соответствие: Auto → успех · Stopped/Manual → нейтральный · Demo → инфо · Error → ошибка · Upgrading/Creating/BackupDB/RestoreDB/Archiving → «в процессе» · Archived → архив · Maintenance → нейтральный с пометкой. Точные значения брать из `Status_DS` ДС, не из старой палитры.

**Горячие клавиши (сохранить):** Ctrl+Enter — «Найти» в поле поиска; Ctrl+Enter — «Отвязать UID» в лицензиях; Shift+Найти / Shift+Click — «связанные» и расширенный поиск.

## 2. Структура прототипа

```
Рабочий стол            — смена: очередь, «требует внимания», мои клиенты
Поиск → результаты      — вход во все сценарии (омнипоиск + таблица)
  └─ Клиент             — карточка клиента 360°
       └─ Сервер        — Обзор · Служба · Логи · История + «Диагностика»
Операции                — диалог операции + Центр задач (очередь и планировщик)
Данные                  — Запросы (SQL/Groovy) · Бэкапы и выдача
Лицензии и Cloud        — статус, операции, маршрут UOC, iikoUser
Мастера                 — тяжёлые операции пошагово (shrink, RMS→Chain, франшиза, …)
```

Все 10 экранов обязательно связать переходами: поиск → результат → клиент → сервер → операция → очередь.

## 3. Экраны

### Э-1. Рабочий стол смены
**Функционал старого интерфейса (переносим):** «Показать очередь» (заброшена, т.к. всегда пуста — делаем работающей), история Scheduler, «Избранные» (не прижились — перезапускаем на новом UX), сведения мониторов заменить на ленту алертов. Монитор процессов — НЕ переносим.
**Сценарии:** SC-02 (ежедн.), SC-18, SC-30; UI-03.
**Состав:** очередь операций (выполняется / в очереди / запланировано / ошибки) с прогрессом; блок «Требует внимания» — каждый пункт с формулировкой действия; мои клиенты / избранное (серверы и демо); лента автодействий «система сделала X»; метрики смены; глобальный поиск в фокусе.
**Состояния:** пусто (новых задач нет — с объяснением «что здесь появится»), загрузка, ошибка с повтором.
**Компоненты ДС:** Card_DS, Table_DS, List_DS, Status_DS, Badge_DS, Button_DS, Tabs_DS (фильтры), Snackbar_DS, Banners_DS (важный алерт).
**Правила:** тех.окна учитываются в «запланировано» (BR-SCH-001); автодействия объяснимы (гипотеза G-20).

### Э-2. Поиск и результаты
**Функционал старого интерфейса (переносим):** поиск по CRM ID / UID (NNN-NNN-NNN) / домену / кластеру / SQL-серверу; пакетный поиск до 1000 значений; WHERE-режим (спецвыражения resto_properties, java_options, idle_middle, node); «Найти» (Ctrl+Enter); счётчик «Кол-во»; лимит 25 результатов + галка «Показать все»; «Экспорт CSV»; автофильтры после поиска (кластер, хранилище, SQL-сервер, версия, статус); Shift+Найти — «связанные» (Chain → RMS и обратно); поиск вне облака через CRM («внешний»); фильтрация по правам (бренд, дилер, демо, HAL); сохранение запроса. Таблица: выбор, Domain, CRM ID, Client, Tomcat, Status, Version, Brand, Memory, DB Size и др.; сортировка; клик по строке → сервер/клиент; иконка BackOffice (.xhosm).
**Переосмысление:** омнибокс с распознаванием типа ввода; чипсы фильтров; сохранённые выборки (вместо cookie на 7 дней); скрытие колонок; метки серверов; пометка on-premise. Поле «Статус» из старого поиска — не переносим (заменяется чипсами).
**Сценарии:** SC-01 (ежедн.), SC-31; UI-01, UI-02.
**Состояния:** обычное / пусто («ничего не найдено» + подсказка про внешних клиентов) / загрузка / ошибка.
**Компоненты ДС:** Search_DS, Chips_DS, Select_DS, Table_DS, Checkbox_DS, Badge_DS, Status_DS, Button_DS, Menu_DS (настройка колонок), Snackbar_DS.
**Правила и тексты:** WHERE только на чтение (INSERT/UPDATE/DELETE/TRUNCATE/DROP/ALTER вырезаются); таймаут WHERE 30 сек; лимит по умолчанию — 25; пакетный поиск до 1000.

### Э-3. Карточка сервера: Обзор · Служба · Логи · История + Диагностика
**Функционал старого интерфейса (переносим по блокам):**
- **Статус:** автообновление (Off / 20 / 60 / 300 / 900 сек; по умолчанию 20; таймаут опроса 5 сек на сервер), «Больше информации», «Внутренний порт», кнопка «Ревизия»; статусы домена (Creating, Auto, Stopped, Upgrading, BackupDB, RestoreDB, Archiving, Archived, Error, Demo, Maintenance); статусы сервиса (RUNNING, STOPPED, N/F, ERR, BAD, N/A, DND); индикаторы проблем (критично мало памяти, метрики в норме, терминал «undefined»); дата последнего старта.
- **Служба:** «Перезапуск» / «Остановка»; опции очистки: «Удалить HostAccess», «Удалить LicState», «Удалить unsaveddata», «Аварийное прерывание»; время исполнения: Сейчас / Очередь / Тех.окно / Через 1–9 ч / ЧЧ:ММ; периодичность D/W/M/Q/Y.
- **Конфигурация:** параметры resto.properties (db-period-length-days, license-fetch-on-start, license-default-iikouid, minimal-front-version, enable-replication, enable-iikoCard5, franchise-server-url, RESTOPROPPACK) и параметры службы (memory / memoryinit, locale, timezone, maxpoolsize, service recreate/demo2prod/prod2demo, idle, javaoptionadd/javaoptiondel).
- **Версия:** версия, branch, показ бета-версий, бренд (Авто/iiko/Syrve), подложить Front/Office, время обновления, флаги Downgrade / Unlock / Rapid; статус предзакачки бэкофиса.
- **Разное:** «Закрыть смену», «Удалить смену» (по одной — списком см. Э-8); ссылки BackOffice / ChainOffice (.xhosm).
- **Диагностика (новый экран-блок):** метрики (память/диск/uptime), топ-ошибки, период, лицензии, смены, чек-лист частых причин зависаний, ссылки в мониторинги.
- **История:** операции, изменения настроек и статусов (кто/когда/что) — новое, закрывает DO-2022/DO-858.
**Не переносим:** «Пароль admin» (запрещено политикой), «Очистить БД» (принято решение не реализовывать), нативную цветовую палитру статусов, «Монитор процессов».
**Сценарии:** SC-02, SC-03; UI-L3-01, UI-D-01.
**Компоненты ДС:** Card_DS, Tabs_DS, Status_DS, Badge_DS, Banners_DS, Expansion-Panel_DS, Slide-Toggle_DS, Checkbox_DS, Select_DS, Input_Number_DS, Timepicker_DS (время операции), Dialog_DS (операция), List_DS (история), Divider_DS, Hint-Tooltip_DS, Button_DS.
**Правила и тексты:** «Аварийное прерывание — только при зависании более 1 часа» (BR-SVC-003); Rapid — только для экстренных случаев (BR-UPD-003); память 512–65536 МБ (текст «Память вне допустимого диапазона»); период 30–3650 дней; по умолчанию период 65 дней, максимум 365 (BR-PRD-001/002).
### Э-4. Диалог операции + Центр задач (очередь и планировщик)
**Функционал старого интерфейса (переносим):** выбор времени операции (Сейчас / Очередь / Тех.окно / Через 1–9 ч / ЧЧ:ММ) и периодичности (D/W/M/Q/Y) — из модулей службы/версии; история Scheduler (showxhosmcronhistory); «Исполнить сейчас»; фильтрация и группировка заданий; отмена задачи (BR-SCH-005); связь с заявкой Pyrus (номер задания в форме обновления, комментарии о результате); посекундный прогресс операций (в старом — WebSocket/Centrifugo на сборках).
**Состав:** 
- **Диалог операции:** заголовок, план до запуска («остановка → запуск → проверка, ≈2 мин, тех.окно не нужно»), время исполнения, периодичность, предупреждения/требуемые подтверждения, кнопка запуска.
- **Центр задач:** список (выполняется / в очереди / запланировано / завершено / ошибки); для каждой — этапы и ETA, автор, время, связь с заявкой; действия: «Исполнить сейчас», «Отменить», «Повторить», «Открыть сервер»; фильтры по типу и статусу; тех.окна отмечены на таймлайне плейсхолдером.
**Состояния:** пусто, загрузка, ошибка; отдельно — «операция ждёт тех.окна» (явная пометка «почему ждёт»).
**Компоненты ДС:** Dialog_DS, Stepper_DS, Select_DS, Timepicker_DS, Checkbox_DS, Radio_Button_DS, Table_DS, Status_DS, Badge_DS, Button_DS, Snackbar_DS, Banners_DS.
**Правила:** задачи в тех.окне выполняются в пределах ночного окна (BR-SCH-001); ежедневные — переносятся на следующий день (BR-SCH-002); временная ошибка — повтор в следующем цикле (BR-SCH-003); при максимуме слотов новые ждут (BR-SCH-004); комментарий в тикет Pyrus по завершении (BR-PYR-002).

### Э-5. Логи
**Функционал старого интерфейса (переносим):** окно с двумя панелями (категории | содержимое); категории: Server (error.log, full.log, startup.log, threaddump.log), Catalina, Archive (текущий), Archive (старый), Front, Franchise; быстрые ссылки: error.log, full.log, JMS.log, startup.log, threaddump.log; кнопка «ZIP» (с опцией ротационных zip-логов), «Egais»; архивные логи доступны при остановленном сервере; создание архива — до 5 минут (показывать прогресс). 
**Переосмысление:** поиск по всем файлам и датам, live-режим, фильтры по уровню, «поделиться ссылкой», пометка разрывов, HTTPS без «403».
**Сценарии:** SC-08 (постоянно при разборах); UI-L3-06, UI-W-01, UI-D-01.
**Состояния:** обычное / идёт сборка архива (прогресс до 5 мин) / ошибка доступа / сервер остановлен (архивные доступны).
**Компоненты ДС:** Tree_DS или List_DS (категории), Table_DS или List_DS (строки лога), Search_DS, Chips_DS (уровни), Button_DS, Tabs_DS, Snackbar_DS.

### Э-6. Данные: Запросы (SQL/Groovy) и Бэкапы
**Функционал старого интерфейса (переносим):**
- **SQL-браузер:** выполнение SQL-запросов (чтение — SQR, запись — SQW), Groovy-скрипты (GRV), макросы-кнопки из Базы Знаний (KB 13, 22, 180, 334 и др.), лимиты: до 1500 серверов за раз, до 100 строк подробного результата (далее CSV), сохранение текста запроса.
- **Бэкапы:** «Бекап из файла» (поиск в АРХИВ / НОЧНЫЕ / ФАЙЛЫ; типы .bak MSSQL / .dmp PGSQL; «На FTP»); «Бекап БД» (тип файла, папка, «Архивировать после», «На FTP», «Анонимизация», «Запустить после»); «Восстановление» (тип, папка, файл, «Пересоздать БД», «Запустить после»); «Перенос/копирование» (SQL-сервер, БД, «Не изменять resto.prop», «Пересоздать БД», «Запустить после», «Удалить исходную»); выдача базы партнёру; авто-бэкап перед downgrade.
**Правила и тексты:** «Если для сервера уже идёт бэкап — ошибка „Процесс уже запущен“» (BR-BAK-001); при копии PostgreSQL предварительно очищается таблица push-уведомлений (BR-BAK-002); анонимизация заменяет персональные данные (BR-BAK-003); ночные бэкапы хранятся 5 дней, ручные — бессрочно (BR-BAK-004/005); перед downgrade — бэкап (BR-BAK-006); тяжёлые SQL — с перезапуском, Groovy — на лету (BR-SQL-001/002); «Закрыть смену» — через БД без Z-отчёта (BR-SPO-001).
**Сценарии:** SC-13, SC-14, SC-09, SC-24; UI-L3-07, UI-L3-08, UI-L3-10, UI-L3-17, UI-W-02, UI-A-02, UI-A-04, UI-I-03, UI-P-03.
**Состояния:** обычное / предупреждение «процесс уже запущен» / прогресс / ошибка с результатом построчно.
**Компоненты ДС:** Textarea_DS (SQL/Groovy), Chips_DS или List_DS (макросы и сохранённые запросы), Select_DS, Checkbox_DS, Input_DS, Dialog_DS, Table_DS (результаты), Snackbar_DS, Button_DS, Banners_DS (опасные действия).

### Э-7. Лицензии и Cloud
**Функционал старого интерфейса (переносим):** модуль «Лицензии»: поле UID / CRM ID; кнопки «Отвязать», «Удалить», «Обновить» (установка лицензии), «goCRM» (переход в CRM), «upRevision» (поднять ревизию), «Обнов. кэш»; Ctrl+Enter — «Отвязать UID»; пароль iikoUser (показывать по праву LIC, «красным», когда выдавать запрещено). 
**Переосмысление (маршрут «красного Cloud»):** upRevision → синк UOC → проверка «облачка» — шаги **одной операции** с результатом на каждом; дерево зависимостей (ЦО / РМС / франшиза); история лицензионных проблем по клиенту; выдача iikoUser как отдельное действие с причиной, сроком и журналом.
**Сценарии:** SC-04 (ежедн.), SC-23; UI-L3-02, UI-L3-15.
**Компоненты ДС:** Card_DS, Chips_DS, Table_DS (история), Button_DS, Status_DS, Banners_DS (запреты и объяснения), Dialog_DS (выдача пароля с причиной/сроком), Stepper_DS (маршрут UOC), Snackbar_DS.
**Правила:** L3 не добавляет лицензии — только устраняет зависшие (BR-LIC-001); кэш обновляется при смене типа оплаты (BR-LIC-002); ревизия — при неактивации при контракте (BR-LIC-003); сброс привязок — при не сбросившихся старых лицензиях (BR-LIC-004); при конфликте — удалить HostAccess.dat и LicensingState.dat + перезапуск (BR-LIC-005).
### Э-8. Списки и массовые операции
**Функционал старого интерфейса (переносим):** множественный выбор галочками в таблице; массовый поиск (до 1000 значений); массовые операции по списку: закрыть/удалить смены (по одной сейчас — делаем списком), обновление, рестарт, SQL (до 1500 серверов), статистика; сохранение выбора при перелистывании; «Экспорт CSV»; массовые действия из результатов поиска.
**Не переносим:** «Групповое создание» серверов (не используется) — остаётся одиночное создание (Э-9).
**Переосмысление:** панель массовых действий появляется при выборе; шаблоны операций («закрыть смены до даты», «очистить + рестарт», «обновить N серверов»); предпросмотр «что будет с N объектами»; порционность с прогрессом по волнам (пример из практики: 6335 серверов — запускать порциями, не более 1000/час); построчный отчёт об успехе и ошибках; «мониторинг → действие» без ручной обработки.
**Сценарии:** SC-11 (часто), SC-19, SC-31; UI-L3-09, UI-A-01, UI-I-04, UI-P-02.
**Состояния:** ничего не выбрано / выбрано N (панель действий) / предпросмотр / выполнение волнами / итоговый отчёт (успех/ошибка по строкам).
**Компоненты ДС:** Table_DS, Checkbox_DS, Button_DS, Dialog_DS (предпросмотр и подтверждение), Stepper_DS или Status_DS (волны прогресса), Snackbar_DS, Banners_DS (предупреждение о нагрузке).

### Э-9. Мастер тяжёлой операции
**Функционал старого интерфейса (переносим — как этапы мастеров):**
- **Создание сервера (NSR):** Домен, Версия, Branch, Beta, Timezone/Locale, Тариф, Кластер, Бренд, Tomcat, SQL-сервер, Эталонная БД, Код страны, «В Чейне», «КЦ»; кнопки «Создать», «Демо».
- **RMS→Chain:** три шага (на RMS: updateReplicationRevisions → на Chain: исправление ServerInstance → updateRmsDepartment).
- **Обрезка базы (shrink):** параметры db-shrink-no-backup, db-shrink-date, db-shrink-exclusive-mode; пометка результата в сервере («не расширять период»).
