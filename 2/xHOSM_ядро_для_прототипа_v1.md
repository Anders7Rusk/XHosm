# xHOSM — ядро для прототипа (боли + сценарии + гипотезы)

**Назначение:** заготовка для задания на отрисовку прототипа нового интерфейса xHOSM. Здесь собраны темы, которые закрывают большинство задач и сценариев интерфейса.
**Как отобрано:** по частоте сценариев (ежедневные → частые → постоянные разборы) и по охвату болей. Получилось **10 тем + сквозной каркас** — это оптимум: меньше — потеряем ежедневные потоки, больше — раздуется задание.
**Источники:** «Боли и проблемы (v2)» · «Сценарии работы (v2)» · «Сценарии интерфейса (v2)» · «Гипотезы (v2)».
**Пометки:** SC-xx — сценарии работы · UI-xx — пути интерфейса · G-xx — гипотезы · DO-/SPRT-/SEC-/PB-/INFRA-… — задачи Jira.

## Темы

### 1. Рабочий стол смены и очередь операций
- **Проблемы:** в смене не видно «что горит»; очередь («Показать очередь») пуста; мониторинги отдельно; автоматика действует молча (бл. 1, 2, 6).
- **Сценарии:** SC-02 (ежедн.), SC-18 (регулярно), SC-30; путь UI-03.
- **Гипотезы:** G-02, G-07.
- **Рисовать:** стартовый экран: очередь операций (выполняется / в очереди / запланировано / ошибки), «Требует внимания» с формулировкой действия, мои клиенты/избранное, лента автодействий, метрики смены, поиск в фокусе.

### 2. Поиск — главный вход
- **Проблемы:** WHERE-барьер; фильтры только после поиска; связи Chain↔RMS неочевидны (бл. 12; SC-01, SC-31).
- **Сценарии:** SC-01 (ежедн.), SC-31; пути UI-01, UI-02.
- **Гипотезы:** G-01.
- **Рисовать:** единая строка: распознавание типа ввода (CRM ID / UID / домен / IP / название), подсказки, чипсы фильтров (кластер, статус, версия, бренд, страна), сохранённые выборки; строка результата («швейцарский нож») с быстрыми действиями; связанные серверы.

### 3. Сервер: статус и диагностика
- **Проблемы:** статусу нельзя доверять («Auto», а по факту STOPPED); рассинхроны xHOSM↔Web; диагностика разбросана (бл. 1, 2; DO-1225, SPRT-32930, DO-1316).
- **Сценарии:** SC-02 (ежедн.), разборы; путь UI-D-01.
- **Гипотезы:** G-03, G-04.
- **Рисовать:** карточка сервера: статус-процесс (остановлен / запускается / стартовал / ошибка + дата старта, источник, свежесть, история, «перепроверить»); блок «Диагностика» одним экраном: красные метрики, топ-ошибки, период, лицензии, смены, чек-лист частых причин зависаний.

### 4. Операции: единый паттерн (рестарт, очистка, период, память, версия)
- **Проблемы:** «непонятно, идёт или завис»; «подробностей не предоставляется» (DO-1431, DO-1536, US-030).
- **Сценарии:** SC-03, SC-05, SC-06, SC-07 (ежедн. / часто); пути UI-L3-01, UI-L3-03, UI-L3-04, UI-L3-05; UI-A-03.
- **Гипотезы:** G-06 (+ G-16 память, G-10 период и конфиг).
- **Рисовать:** диалог операции: план до запуска («остановка → запуск → проверка, ≈2 мин, окно не нужно»), шаги с прогрессом и ETA, результат построчно, уведомление; для памяти — расчёт с объяснением и «времянки» со сроком; для периода — видимый срок и авто-возврат.

### 5. Логи
- **Проблемы:** «нет chain of custody», разобраться «невозможно без посвящённого»; нет zip по диапазону; 403/HTTPS; логи фронта недоступны (DO-899, DO-1516, DO-936, DO-1179, DO-1197).
- **Сценарии:** SC-08 (постоянно при разборах); пути UI-L3-06, UI-W-01.
- **Гипотезы:** G-11.
- **Рисовать:** вкладка «Логи»: поиск по всем файлам и датам, live-режим, фильтры по уровню, ZIP за диапазон, «поделиться ссылкой», архивные логи при остановленном сервере, пометки разрывов.

### 6. Данные и запросы: SQL/Groovy, бэкапы, выдача
- **Проблемы:** смены чистят скриптами + пересчёт в вебе; Bcrypt через Groovy; бэкап «уезжает» к DevOps; выдача партнёру — FTP с новым паролем; анонимизация — отдельным сервисом (SC-15-контекст, SC-24, DO-1679, DO-1917, DO-1602).
- **Сценарии:** SC-13, SC-14 (ежедн. / периодически), SC-09, SC-24, SC-20; пути UI-L3-07, UI-L3-08, UI-L3-10, UI-L3-17, UI-W-02, UI-A-02, UI-A-04, UI-I-03, UI-P-03.
- **Гипотезы:** G-13, G-12, G-25 (копилка запросов).
- **Рисовать:** блок «Запросы»: сохранённые SQL/Groovy команды с шарингом и запуском с прогрессом; блок «Бэкапы»: где лежат и сколько хранятся, создание с дефолтным путём, выдача партнёру в одно действие (+ анонимизация).

### 7. Лицензии и Cloud
- **Проблемы:** «красный Cloud» лечится в трёх системах (xHOSM → Postman → админка); рассинхрон статусов; iikoUser выдаётся бесконтрольно (SC-23, SPRT-32930, PB-3813).
- **Сценарии:** SC-04 (ежедн.), SC-23; пути UI-L3-02, UI-L3-15.
- **Гипотезы:** G-19 (+ G-24 iikoUser, G-14 лицензии в карточке).
- **Рисовать:** блок «Лицензии»: статус Cloud/UOC, дерево (ЦО / РМС / франшиза), операции (отвязать / обновить / удалить / кэш), маршрут «привести в порядок»: upRevision → синк UOC → проверка «облачка»; iikoUser: выдача с причиной, сроком и журналом.

### 8. Смены и массовые операции
- **Проблемы:** 100+ смен по одной, «ооочень долго»; 6335 серверов рестарта вручную; массовые дают 502 (DO-969, DO-1745, DO-1622, IA-661).
- **Сценарии:** SC-11 (часто), SC-19 (регулярно), SC-31; пути UI-L3-09, UI-A-01, UI-I-04, UI-P-02.
- **Гипотезы:** G-08.
- **Рисовать:** списки с галочками и «выбрать всё по фильтру»; шаблоны («закрыть смены до даты», «очистить + рестарт»); предпросмотр «что будет с N объектами»; порционность и прогресс по волнам; построчный отчёт; «мониторинг → действие» без ручной обработки.

### 9. Мастера тяжёлых операций
- **Проблемы:** shrink — 10+ шагов с ручным вводом; RMS→Chain — цепочки; перенос БД без бэкапа затирал базы; франшиза вручную; восстановление из архива (SC-15, SC-16, SC-21/22, SC-32; DO-1602).
- **Сценарии:** SC-15, SC-16, SC-10, SC-17, SC-21, SC-22, SC-32; пути UI-L3-11, UI-L3-12, UI-L3-13, UI-L3-14, UI-L3-16, UI-I-01, UI-I-02.
- **Гипотезы:** G-09.
- **Рисовать:** пошаговый мастер: шаги с проверками, автоподстановка параметров, авто-бэкап перед опасным шагом, пометки результата (shrink), прогресс, откат при ошибке, финальный отчёт.

### 10. Карточка клиента 360°
- **Проблемы:** контракт и корневой дилер — только в CRM; тариф «непонятно откуда»; кластеры крупных баз держат в голове (бл. 4; DO-1329, DO-1250, DO-1436, DO-1738).
- **Сценарии:** SC-20, SC-17, SC-04; пути UI-P-01, UI-P-03.
- **Гипотезы:** G-14 (+ G-18 партнёрский вид, G-23 режимы).
- **Рисовать:** карточка клиента: контракт (включая архивный), корневой дилер, бренд, тариф; лицензии (UID, iikoUser, Cloud); серверы и связи; параметры (память, период, версия); признак «крупная база»; история и быстрые действия.

## Заготовка состава экранов (для задания на отрисовку)

1. Рабочий стол смены (очередь, «требует внимания», мои клиенты)
2. Поиск + результаты (строка результата, чипсы, сохранёнки)
3. Карточка сервера — Обзор / Служба / Логи / История + «Диагностика»
4. Диалог операции (план → шаги → результат) + Центр задач / планировщик
5. Логи (вьюер с поиском, live, zip, share)
6. Данные: «Запросы» (SQL/Groovy) + «Бэкапы и выдача»
7. Лицензии и Cloud (статус, операции, маршрут UOC)
8. Списки с массовыми действиями (смены, мониторинг) + шаблоны
9. Мастер тяжёлой операции (пример: shrink или RMS→Chain)
10. Карточка клиента 360°
